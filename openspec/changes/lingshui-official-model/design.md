## Context

现有生成器专用于开发区，地图与物理边界对非开发区采用 180 米占位范围。官方主校区接口包含同 ID 多段道路及周边居民区；轮廓不含楼高。主楼等照片可支持部分外观，原始照片仅作离线参考。

## Goals / Non-Goals

**Goals:** 保留官方多边形与 ID，独立生成凌水资源；以照片核对重点立面；地图与碰撞按主校区数据范围接入。

**Non-Goals:** 不生成室内，不推测地形高程、未见立面、树木分布；不制作周边其他单位与住宅小区；不改变现有产品交互或引入流式加载架构。

## Decisions

- 使用官方经纬度转局部 X 东、Z 南的近似米制坐标；明确筛选规则与排除清单，保留同一 ID 的所有分段，避免只按 ID 去重丢失道路。
- 独立凌水数据准备与模型生成工具，复用已有几何工具而不对开发区生成逻辑大规模重构。重点建筑的照片立面独立模块维护。
- 未有照片的建筑采用中性自然材质轮廓实体，不添加通用窗格；照片可确认的立面再添加窗、石材分隔和屋檐。楼高估计和每个立面的照片来源写入数据。
- 道路使用官方多边形，地图直接绘制；专属数据提供校园矩形底座范围，运行时建立对应边界。底座不代表官方校园红线。
- 保留实体碰撞与装饰分离，按材质合并每栋建筑细节，避免数万个独立窗框节点；不改变其他校区资源。

## Risks / Trade-offs

- [高度与坡度缺失] → 楼高明确标注估计，地面统一平面，不伪造山体和坡道。
- [照片并非全立面] → 只在能够核对的边上添加细节，其他边保留轮廓。
- [源多边形复杂或重复] → 检查三角化、分段数和 ID；不静默丢弃错误轮廓。
- [Web 性能] → 合并装饰网格，避免透明玻璃与新增灯光，实际导出渲染并检查传送。
