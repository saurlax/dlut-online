## Context

已有第一人称 CharacterBody3D 及原生封面，场景切换重建玩家。工作区另有未提交的资源包变更，须保持独立。

## Goals / Non-Goals

**Goals:** 为第一人称玩家提供会话内稳定的身份、原生游客入口与昵称。

**Non-Goals:** 本次不扩展角色外观编辑或持久服务端账户。

## Decisions

使用预加载 RefCounted 脚本的静态状态跨场景保存身份，避免更改已在进行其他工作的项目配置。Godot Crypto 生成 16 字节随机十六进制 ID；昵称为“游客”加从 ID 导出的六位数字。存储键为 do_guest_id，校验后复用，损坏则重建。仅浏览器地址读取和会话存储适配通过 JavaScriptBridge；字符串只使用已验证的十六进制 ID。相比 localStorage，sessionStorage 符合用户要求的会话生命周期。桌面只在进程内保存。

封面保留产品名称，增加昵称和游客登录按钮。身份在封面准备，登录点击后绑定玩家再进入。失败时显示可重试的存储错误，不假装已保存身份。保持第一人称控制、角色胶囊与相机参数。

## Risks / Trade-offs

- sessionStorage 可由用户修改 → 只作本地游客标识，不能用作未来服务端鉴权凭据。
- 浏览器禁用存储 → 阻止进入并提示重试。
- 浏览器复制标签或恢复关闭的会话可能复制/恢复 sessionStorage → 遵循浏览器行为，不承诺每个标签全局唯一。
- 六位昵称可能重复 → 完整随机 ID 才是身份。

## Multiplayer Protocol

Go 使用 Gorilla WebSocket，在 `/ws` 接收 hello（id、campus、position、yaw），返回 welcome 和每秒 10 次同校区快照。服务器派生昵称，校验 ID、校区、有限位置和朝向、消息大小和发送频率；同 ID 新连接替换旧连接。浏览器校验同源 Origin，桌面允许无 Origin。客户端每秒发送 10 次状态，用插值显示其他玩家，切换场景关闭旧连接、清除旧代理。断线后自动退避重连，地图显示连接状态。游客 ID 不是认证凭证，当前同步为客户端位置上报，不提供防作弊或玩家间碰撞。

远端角色为自然比例的简洁人形代理（头、躯干、四肢），仅用于表示联机玩家，独立于世界模型和本地胶囊碰撞。Web 使用原生 WebSocketPeer 和浏览器同源地址读取；桌面使用现有服务器配置。
