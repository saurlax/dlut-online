## Context

动机见 proposal.md。现有 Go `players.go` 每连接独立生成 10 Hz 同校区快照；Godot 使用原生 WebSocketPeer 和 JSON，并直接上报位置。`player.gd` 混合输入、相机和运动，`campus.gd` 混合碰撞生成与 UI 初始化。没有数据库、真实 SSO 或站点首页。

## Goals / Non-Goals

**Goals:** 保留第一人称交互与三校区传送，实现服务器权威运动、单公开源入口以及可验证时效的在线查询。容量目标为单游戏实例总计 50 人，无额外分房间。

**Non-Goals:** 本次不建设真实 SSO、数据库、历史报表、活动或资产交易；不承诺通用反外挂。未来集成只定义职责和数据边界，不预建空模块。

## Decisions

### 进程、目录与碰撞来源

Go 保留 `apps/web/`，避免无必要迁移。Godot 服务端使用 `apps/game/` 同一 Godot 工程内独立的 `scripts/server/` 脚本目录和 `scenes/server.tscn` 入口、Linux 专用服务端导出预设，构建到 `build/server/`。Web 与桌面客户端导出明确排除服务端入口及专属代码。不维护第二套 Godot 工程或校园源模型。

把运动规则拆为客户端和服务端共用的纯运动部分；输入、相机、网络、UI 留在各自职责内。碰撞生成器从现有校园场景、注册表及明确碰撞标记导出独立静态碰撞场景，包含边界与出生点，不实例化客户端 `campus.gd`。客户端与服务端使用同一来源和版本的碰撞规则，检查生成结果一致性。服务端不加载视觉模型、纹理、灯光、UI 或资源下载器；碰撞生成必须先于剥离网格，不能因专用服务器资源剥离失去 trimesh 来源。

单游戏进程以独立 World3D 为三个校区隔离物理空间，避免相同坐标发生跨校区碰撞。服务端允许同时持有三个碰撞世界；原有“场景切换卸载旧校区”约束继续适用于客户端，不同时加载三个视觉校园模型。实施时同步 AGENTS.md 的服务端例外。为 50 人部署三个独立游戏进程会增加路由、身份互斥和汇总复杂度，因此本次不采用。

### 公开入口与服务边界

浏览器仍访问同源 Go，`DO_SERVER_URL` 保持 HTTP(S) 根地址定义及现有开发/生产默认值。

| 方向 | 路径/消息 | 数据及职责 |
|---|---|---|
| 浏览器 → Go | `GET /`、`/web/` | 简洁进入游戏链接及官方 Godot 导出资源；不增加管理后台或游戏内 HTML UI |
| 客户端 → Go | `POST /api/v1/game/tickets` | 协议版本、游客 ID；返回一次性短期票据和相对 `/ws` 路径 |
| 客户端 → Godot，经 Go 代理 | `/ws` | hello、input、welcome、snapshot、切图请求/就绪确认、心跳、错误与关闭；Go 不解析/维护玩家游戏状态 |
| Godot → Go | `POST /internal/v1/game/tickets/consume` | 一次性兑换入场票据，返回可信身份与连接代次 |
| Godot → Go | `POST /internal/v1/game/register` | 登记实例启动标识并获取本次上报代次；注册重试使用同一请求标识保持幂等 |
| Godot → Go | `POST /internal/v1/game/presence` | 实例、启动代次、递增序号、在线玩家摘要，完整覆盖快照 |
| 外部查询 → Go | `GET /api/v1/game/online` | 总人数、分校区人数、状态时效；不暴露玩家明细 |
| 授权运维 → Go | `GET /api/v1/admin/game/players` | 当前在线玩家标识、昵称、校区、入场时间，附相同时效信息 |

Go `/ws` 使用标准反向代理支持 Upgrade，继续执行浏览器同源 Origin 校验，桌面允许无 Origin。Godot 监听内网，生产以网络策略阻止外部直连，但自身仍验证票据及消息。不用 Godot 高层多人协议，继续 JSON，方便协议版本管理和独立自动化测试。

新增项目配置统一 `DO_`：Go 的 `DO_GAME_SERVER_URL` 指向内网 HTTP 根地址，Godot 用 `DO_API_SERVER_URL` 访问 Go；`DO_GAME_LISTEN_ADDR`、`DO_GAME_PORT`、`DO_GAME_INSTANCE_ID` 配置游戏监听与实例标识。双方使用 `DO_GAME_SERVICE_TOKEN` 验证内部请求；独立 `DO_ADMIN_API_TOKEN` 只读查询玩家明细，不能签发内部身份。凭据仅服务端读取，不导出到客户端、不写入镜像或日志；生产缺失凭据拒绝启动，开发使用显式本地配置，不设置通用默认密钥。保留 Go `PORT` 与 `-addr` 兼容。

### 入场与游客身份

Go 以加密随机数产生不透明票据，服务端内存保存，默认 30 秒有效；绑定身份种类、游客 ID、派生昵称及协议版本，不包含地图或校区访问权限。票据经 HTTPS 返回并放在 WebSocket hello 正文，禁止 URL 查询参数，防止访问日志泄露；限制签发频率和待兑换总量，过期项及时回收。

兑换需要内部凭据，以原子操作消费一次。兑换成功但响应丢失时不重复入场，客户端重新请求票据。所有 HTTP 操作有截止时间，Godot 异步等待；未验证连接不进入物理世界、不计在线。游客入口仍不证明现实身份，知道游客 ID 的人仍可申请同名游客会话，不能访问敏感账户数据。

Godot 对同身份只保留一个活动连接，欢迎响应返回连接代次；同 ID 新连接替换旧连接并发送 4001，旧客户端停止重试。异步处理和断开回调必须核对连接代次，防止旧连接清掉新玩家。满 50 个不同玩家时拒绝新身份，允许已有身份合法替换。只有首次连接或真实断线后重连才重新取票。同一游戏实例内切图保留 WebSocket、身份、连接代次和入场时间，不调用 Go 签发或兑换票据。三个校区对所有玩家开放，游戏服只验证地图 ID 是否存在；新校区出生点由服务端决定；客户端保留身份但不重复显示登录封面。

未来真实 SSO 只替换 Go 中的身份建立过程，仍走同一入场票据接口。真实账号使用 SSO issuer 与 subject 的可信映射，不将昵称、游客 ID 或客户端声明当作账号。SSO 协议、回调地址和会话撤销策略待后续真实接入任务确认，不虚构供应方或预留可用假登录端点。

### 同连接切图与场景生命周期

客户端网络管理节点采用 Autoload，持有 WebSocket、心跳、会话和切图状态，独立于校园场景及玩家节点。场景退出只解绑角色、清理远端实例，不关闭连接；新场景就绪后重新绑定本地角色。心跳与网络 poll 在暂停、加载和地图打开时继续运行；资源下载/加载使用异步方式，避免主线程长时间阻塞心跳。服务端专用入口不启动客户端网络 Autoload 的连接逻辑。

同连接切图采用以下流程，不重新 hello 或验证身份：

1. 客户端停止移动，发送 `change_map`（request_id、目标 campus）。服务端验证地图存在，为本连接创建唯一 transfer_id，保存原地图与权威位置，冻结角色并返回 `map_prepare`。此时玩家仍属于原校区且计在线，旧校区角色保持静止。
2. 客户端异步下载目标启动资源，成功后使用 SceneTree 切换并卸载旧场景，一次只实例化一个校园。目标碰撞和本地角色就绪后发送 `map_ready`（transfer_id）。准备阶段不发送移动输入，不应用旧地图快照到目标场景。
3. 服务端收到有效 ready 后，在一个模拟边界原子迁移玩家：从原校区名册移除、移到目标出生点、清空旧输入、递增 map_epoch，并返回 `map_entered`（transfer_id、campus、map_epoch、权威状态及完整名册）。只有此时更新玩家的统计校区。
4. 客户端收到 entered 后绑定权威状态，清空旧预测/插值缓存，恢复进入游戏前的交互状态。新输入、快照均携带 map_epoch；服务端拒绝旧代次输入，客户端忽略旧地图快照。持续自状态快照携带当前地图代次和最近切图结果，控制响应按 request_id/transfer_id 有界缓存，重复消息返回既有结果而不重复迁移。

同一连接至多有一个切图请求在进行，另一个请求返回 busy，不能交错提交。无效地图请求不改变原状态。资源失败、取消或准备超过 180 秒时，服务端回到原地图保留的位置并递增 map_epoch、清空输入；客户端通过 `map_cancel` 或 `map_status` 获取最终结果，必要时重新加载原场景并发送 `map_resume` 确认就绪后恢复移动，过程中仍不重连。ready 与 cancel 的竞争按服务端先处理的有效提交决定；已提交的切图不能被迟到的 cancel 回滚，客户端以最终权威结果加载对应地图。迟到 ready、旧请求回调不得创建重复角色或切回旧地图。结果未知时请求状态，不通过再次取票解决。

心跳每 5 秒发送，独立于移动上报；15 秒无有效消息的连接超时也接受有效心跳续期，不能因为加载期间没有 input 就误断线。准备和回退加载期间服务端保持角色冻结；输入超时只负责停止移动，不替代切图状态。真实断网仍走原有退避重连及新票据流程，清理旧 transfer_id，不能复用上次连接的切图确认。

### 权威模拟与协议

协议标记 `version: 2`。hello 携带票据及独立的目标 campus 字段，默认 lingshui；地图选择不参与票据签发或兑换，不携带可信初始位置；welcome 返回服务器身份、校区、连接代次、物理 tick、出生状态。旧版 state 消息、未知版本明确拒绝。

input 包含递增 `seq`、二维本地输入轴、有限 yaw、run 布尔值、jump 请求序号；不接受客户端速度、delta、位置或任意玩家 ID。客户端每秒至多 20 次上报，暂停/失焦/打开地图立即发零轴；跳跃请求序号防止同一次按键重复执行。服务端每秒 60 个固定物理步，用最新有效输入模拟；一个 tick 至多应用一次运动，轴归一化、速度/重力/跳跃/落地判定/跌落复位来自共享现行规则。500 ms 没有有效输入停止水平运动，15 秒无有效消息关闭连接。限制消息大小为 2 KiB、每连接每秒 40 条输入及有界握手等待和发送缓存；泛洪不能增加模拟次数。

每校区每 100 ms 生成和序列化一次快照，复用给该校区连接。快照携带 server_tick、campus、玩家 ID、位置、速度、yaw、已消费输入 seq 和跳跃序号，包含本地玩家供纠正。昵称在入场名册中发送，避免每个快照重复；加入/离开可靠通知，定期完整名册用于恢复一致性。慢连接只保留应用层最新待发快照，检查传输缓存，超过上限断开，不能无限排队；WebSocket 已写入 TCP 的旧数据不可撤回。

客户端本地用相同规则预测，权威状态纠正物理体，视觉位置用短时平滑偏移消除小跳变；远端角色插值。必要时重放有界未确认输入，但不能假定调用 move_and_slide 多次就得到跨端确定性物理；是否重放由延迟验收决定，至少必须消费本机权威位置而非只更新远端。断线期间停止有效移动，避免客户端走远后出现大幅回拉。测试覆盖 100–200 ms 往返延迟的行走、跳跃、墙边和坡道纠正。

### 在线状态与查询

Godot 启动时经内部认证注册启动代次，Go 返回本次有效代次；每 5 秒发送完整在线快照，包含 instance_id、该代次、seq 和 players（身份种类、ID、昵称、校区、入场时间）。Go 按已登记代次验证单调序号，以服务端接收时间计时，只接受当前代次，延迟旧包不能覆盖新状态。切图全程按同一在线玩家计数，保留入场时间，提交时才原子更新校区，不生成退出/重新登录事件；准备阶段归原校区。正常零人仍发送空快照。实例重启必须新注册，旧代次永久失效于当前 Go 进程。

Go 超过 15 秒未收到有效快照，公开接口返回 stale 且当前人数为 null，启动后从未同步返回 unavailable；可附最后观测人数及 received_at，但不得把未知显示成零或继续声称在线。玩家明细采用同一规则。Go 重启丢失内存注册时，Godot 自动重新注册并发完整快照；恢复后才重新报告 live。状态接口禁用响应缓存。

Go 数据接口故障不阻塞现有玩家物理或快照。新入场需要兑换，故障时明确失败；在线上报使用有界超时与退避并合并为最新快照。Go 网关进程本身重启会断开代理连接，客户端自动重连，不能宣称所有 Go 故障都无感。

本次只提供实时查询，不持久化轨迹，不提供假 DAU、留存、历史时长或空壳图表。公开仅聚合人数；玩家明细需要独立管理凭据，不公开坐标、SSO 信息或票据。

### 后续数据库和外部查询契约

这部分是后续扩展说明，不在本次创建数据库或 API 空实现。Go 是持久数据的唯一写入入口，游戏服务器是活动世界状态的负责人。

| 将来流向 | 典型数据 | 一致性要求 |
|---|---|---|
| Godot → Go，入场读取 | 账号资料、允许的出生记录 | 超时失败不能伪造读取成功；验证数据版本 |
| Godot → Go，周期保存 | 校区、位置、玩家设置 | 身份、session_epoch、revision；旧会话/旧版本不能覆盖新数据 |
| Godot → Go，重要业务操作 | 用户未来明确要求的交易 | operation_id 幂等、数据库事务，提交成功后确认 |
| Godot → Go，分析事件 | 加入、离开、校区切换 | event_id、session_id、服务端时间；幂等落库，崩溃缺失离开事件需标为推算 |
| Go → 外部 API | 学校公开或获授权的数据 | 服务端凭据、超时、限流、缓存；按授权决定是否转给客户端 |
| 客户端 → Go | 查询本人资料或站点数据 | Go 认证授权，不借助游戏输入消息绕过权限 |

实时位置不逐 tick 落库；只在退出保存不可靠，采用周期保存和关键节点保存。缓存过期策略按具体外部数据制定，不在本次臆造。初期不引入消息队列、Redis 或微服务框架；对需要崩溃后不丢失的事件，再引入持久 outbox 等可靠机制。

## Risks / Trade-offs

- [TCP 弱网排队与预测差异] → 有界缓存和输入队列、快照合并、真实延迟测试；不承诺消除所有回拉。
- [权威物理消耗大于当前 Go 转发] → 只加载碰撞；50 人持续移动压测，记录机器、CPU/内存、出口、tick 延迟和队列情况，不把估算当结果。
- [服务端复制客户端世界带入 UI 或视觉资源] → 独立入口、共享生成器和导出清单检查，三校区隔离物理测试。
- [在线内存状态不是历史分析] → API 明确 freshness 与 unavailable，后续数据库任务再实现历史事件。
- [新增内部信任边界] → 独立服务凭据与管理凭据、票据一次性消费、限制请求大小/数量、生产 TLS 和私网部署。
- [共享项目可能泄露服务端配置] → 凭据只运行时注入，客户端导出排除专属代码与配置；同时保证服务端保有必需碰撞。

## Migration Plan

1. 实现共享运动/碰撞和 Godot 服务端，再接 Go 票据、代理和在线接口；删除旧 Go 广播实现及无用依赖，保留相关约束测试并迁移到新协议。
2. 同版本导出 Web、桌面、Godot 服务端，并构建 Go 与 Godot 两个独立镜像。提供本地双服务启动与容器联通配置，CI 验证真实入场和在线计数。
3. 协调发布客户端和服务端，旧连接在维护切换后重连，旧协议提示刷新/升级。保持 `/web/`、`/ws` 和公开根地址不变。
4. 更新 README、Go 文档、AGENTS.md 及被取代的游客同步决策，保留历史完成记录但明确新约定的优先级。
5. 回滚必须同时回滚客户端、Go 和游戏部署版本，不能混用新输入客户端与旧位置转发服务。此次无数据库迁移，不承诺重启保留在线位置。
