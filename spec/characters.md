# 角色外观与穿戴

## 状态与范围

已实现原生人物、四向预览与本地行走、账号注册登录、角色创建、初始衣物、背包装备和 3×10 格物品栏。当前肤色、发型与发色各 4 种，脸型、鼻子、嘴巴、眉毛、胡须与雀斑各 2 种，眼色 3 种。眼型、独立眉色与胡须色、外套、扩展配饰及创建后重新捏脸尚未实现，下文对应部分为后续设计目标。

角色由身体外观和穿戴物品共同组成。身体外观存于角色，衣物归玩家所有并具有独立物品身份；创建角色时选择的初始衣物需要实际发放，不能只是永久贴在人物上的外观字段。

## 身体外观

| 部位 | 可定制内容 | 表现约定 |
| --- | --- | --- |
| 肤色 | 成组的明暗色板 | 脸、耳朵、手臂与腿使用同一色板 |
| 脸型 | 少量脸部轮廓模板 | 保持统一头部锚点，不连续拉伸 |
| 发型 | 短发、长发、刘海等完整款式 | 素材拆前发与后发，玩家选择完整发型 |
| 发色 | 发型使用的色板 | 发色不影响帽子和衣物 |
| 眼睛 | 眼型、瞳色 | 正面与侧面分别绘制，背面不显示 |
| 眉毛 | 眉型、颜色 | 与眼睛在同一头部坐标内组合 |
| 鼻子 | 少量鼻型，含简化款 | 使用原生像素模板，不增加高分辨率细节 |
| 嘴巴 | 少量嘴型 | 静态轮廓与未来表情分开，不让嘴型锁定表情 |
| 面部特征 | 雀斑、痣等可选模板 | 使用明确组合模板，首批不叠加任意多层 |
| 胡须 | 无胡须或胡须款式、颜色 | 身体外观的一部分，不是可放入背包的物品 |

首批使用统一身体比例，所有服装共用动作模板。体型和身高滑杆暂不加入；增加身体模板前，先解决已有衣物对各模板的适配。服装不按性别限制。

## 穿戴物品

| 槽位 | 对应物品 | 建设顺序 |
| --- | --- | --- |
| 头部 | 帽子 | 首批 |
| 上装 | T 恤、衬衫等 | 首批 |
| 下装 | 长裤、短裤、裙子 | 首批，同占下装槽位 |
| 鞋履 | 一双鞋 | 首批，按双持有和穿脱 |
| 外套 | 夹克、开衫等 | 后续，覆盖上装而不替换上装 |
| 眼部配饰 | 眼镜 | 后续 |
| 面部配饰 | 口罩 | 后续，与眼镜独立 |
| 颈部配饰 | 围巾等 | 后续 |
| 背包 | 校园背包、旅行背包、登山背包 | 已实现，分别提供 10、20、30 格容量 |

衣物款式属于物品定义，具体颜色属于玩家拥有的物品实例。选择初始衣物颜色会决定赠送物品的颜色，不写进肤色或身体外观。首批不引入连衣裙等跨槽位物品，避免上下装占用规则尚未明确时混用。

所有穿戴槽位允许为空。脱下上装或下装时，身体底图保留基础内衣；基础内衣不生成物品。脱鞋显示身体底图中的脚，摘帽恢复原发型。帽子可以遮住刘海或后发，但不修改存储的发型。

## 创建角色与初始衣物

1. 玩家选择身体外观，再从初始衣物目录选择上装、下装、鞋履；帽子可以选择不戴。
2. 预览提供正面、背面和左右侧面，展示实际角色像素，不另外绘制无法对应游戏人物的精细头像。预览选择不产生物品。
3. 玩家确认后，服务端在同一次持久化事务中创建角色、发放所选衣物实例并将其放入对应穿戴槽位。选择了帽子时同时发放帽子；另发放并直接穿上 10 格校园背包，物品栏为空。
4. 创建成功后进入校园。已穿在身上的初始衣物属于玩家，之后可脱下放回背包，与其他同类衣物遵循相同规则。

初始衣物按角色成功创建发放一次。重复提交创建操作返回同一创建结果，不重复发衣物。后续修改脸、五官或发型不再次发放衣物，也不覆盖已有背包与穿戴。

角色名与身体外观分开保存，当前每个账号一个角色，不增加多角色选择界面。

## 物品归属与穿脱

每件衣物实例只有一个位置：物品栏格、背包格或穿戴槽。装备栏与背包展示的是同一批自有物品，不为已穿戴衣物另保留一份背包副本。

- 未穿背包时仍有独立的 10 格物品栏可以存放物品；背包窗口始终保留 3 行、每行 10 格的占位图，未开放格显示锁定图案，不能放入或选择。
- 穿上背包按物品定义开放 10、20 或 30 格，上限 30 格。初始校园背包直接穿上，开放第一行。
- 物品栏和背包中的衣物都可以穿上，同槽装备换回此次腾出的存储位；每件物品始终只有一个持久化位置。
- 脱下装备优先放入空物品栏格，其次放入已解锁空格；没有空间时拒绝。脱背包只能放入物品栏，且所有将锁定的格子必须为空。
- 更换小背包时按交换后的最终状态验证容量，包含被替换背包将占用的格子；不能把物品留在锁定格，也不自动丢弃或删除物品。
- 存储位之间支持移动和交换；物品栏不穿戴衣物，独立于 30 格背包容量，最大存储量为 10+30 格。穿脱和位置变化由服务端在事务中确认并持久化，客户端不能直接写归属和位置。
- `I` 或底部 `I` 按钮打开背包窗口，重复按 `I`、Escape 或点击窗口外收起，不显示退出账号或返回按钮；输入表单和其他窗口不响应背包快捷键。窗口左侧显示实际人物与转身按钮，右侧为帽子、上装、下装、鞋子、背包槽与当前手持物品预览（复用当前所选物品栏格，不增加存储空间），下方先放 3×10 背包格，再放独立 1×10 物品栏，共四行格子和所选物品操作。
- 底部快捷物品栏始终显示独立 10 格，与窗口最下一排相同，`1`–`9`、`0` 对应第 1–10 格，点击或数字键切换当前选择，不受背包容量影响。切换仅改变当前快捷选择，不复制或移动物品，选择暂存在当前页面。
- 点击格子选择物品，用穿上、脱下、移至物品栏、放入背包按钮操作；双击物品执行穿脱，拖放支持存储位交换和拖到匹配装备槽。未登录或未创建角色时，背包入口显示账号或角色创建表单。

本功能不添加交易、商店、货币、物品使用效果或升级获取途径。旅行背包和登山背包有物品定义与容量规则，初始只发校园背包。

## 像素素材与动画

人物身体以原生 16×32 像素为基准，参考星露谷人物的尺寸和分层方式，素材自行制作。人物允许跨越两个 16×16 地面格；地面瓦片尺寸不要求人物也画进一个正方形格子。

角色、衣物、头发与五官使用相同原生像素密度，按[前端共享显示网格](frontend.md)的倍率显示。保持二值透明与最近邻显示，不在运行时把高分辨率人物压缩成伪像素素材。帽子或长发超出身体帧时可以增加原生像素画布和登记偏移，脚底锚点及像素密度不变，不单独缩放配件。

16×32 是美术画幅，不直接等同于角色真实身高或碰撞高度。碰撞使用脚底占地，头部和帽子不参与地面占用；人物与建筑、树木按脚底落地点处理前后遮挡。

首批包含四向站立与行走。所有身体与穿戴层共用方向、帧序、动作时间和脚底锚点。五官在实际可用的少量像素内提供差异，放大预览也不补画额外细节。

渲染按方向和动作确定层序：后发、背部物品、身体、下装与鞋、上装、外套、五官、前发、帽子及前侧手臂等。该顺序不是所有动作通用的固定堆叠；手臂、衣袖、长发与配饰需要对应朝向的遮挡片，避免侧面穿帮。首批素材先核对帽子与头发、裤脚与鞋、衣袖与手臂的组合。

## 数据与多人同步

身体外观记录款式 ID 和色板 ID；物品定义记录槽位、素材与可用颜色；物品实例记录唯一 ID、归属、定义、颜色和位置。服务端从这三类数据生成角色的可见外观，不把完整背包广播给其他玩家。

外观变更与穿脱属于可靠业务操作，沿用[多人通信](networking.md)的可靠控制消息与操作去重规则。初次进入可见范围时下发完整可见外观，后续变化带外观版本，防止较旧穿搭覆盖新穿搭。移动快照不反复携带完整衣物数据。

## 实现顺序

1. 制作一个基础身体及四向站立、行走，组合一套可独立替换的头发、五官和衣帽鞋裤，验证地图比例、显示颗粒与遮挡。
2. 增加外观选项和创建预览，按上述分类组织捏脸与初始穿搭。
3. 接入角色持久化、初始衣物发放、背包与穿脱，使创建和换装形成完整流程。
4. 在多人会话接入时同步服务端确认的可见外观，再逐步增加外套与配饰素材。

## 当前运行约定

WASD 或方向键以每秒 32 原生像素（2 米）本地移动；按住 Shift 疾跑为每秒 64 原生像素（4 米），松开恢复步行，疾跑时行走动画同步加快。两种速度均保持斜向归一化，倍率固定，人物可走出原视野并触发镜头跟随；横纵方向 25%–75% 区间内镜头不动，越界后跟进，地图边界优先。草地、林地地面、运动场草坪、道路、红步道、跑道、球场、铺装与桥面可通行，建筑占地阻挡通行，水域、岸坡和地图外不可通行；尚无精细植被碰撞、触屏移动和多人权威位置。失焦或打开模态窗口清除移动输入。初次落点在登记焦点附近寻找可行走地面，穿脱保留当前位置。

账号令牌按浏览器标签页保存在 sessionStorage，刷新时验证并续期，退出账号清除。昵称与外观、物品数据保存于 PocketBase。
