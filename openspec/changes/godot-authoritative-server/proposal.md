## Why

当前 Go `/ws` 只转发客户端位置，不能通过校园碰撞验证移动，也把实时世界与站点职责放在一起。将世界模拟迁到 Godot，可复用现有运动与碰撞数据，让 Go 专注站点、认证接入和可查询的运营数据，支持预计最多 50 人在线。

## What Changes

- 增加 Godot 无头服务端入口，服务端决定出生点、移动、跳跃与校区归属，客户端发送输入并执行预测与纠正。
- **BREAKING**：替换现有位置上报协议，增加协议版本；旧客户端明确拒绝，不回退到信任客户端位置。
- Go 保留 `apps/server/`，负责 `/web/`、简洁站点入口、`/api/v1/` 和 `/ws` 反向代理；移除 Go 玩家模拟/广播职责。
- Go 签发短期游客入场票据，Godot 通过内部认证接口一次性兑换，票据不绑定校区，三个校区均为所有玩家开放的地图；未来 SSO 映射到同一身份与入场流程，游客 ID 本身仍不是账户凭据。
- Godot 向 Go 定期上报带实例、启动代次、序号及有效期的在线快照；Go 提供公开人数和受保护的在线玩家查询，过期数据标为不可用。
- 明确未来持久化、SSO 和外部 HTTP 查询的通信契约；本次不接真实 SSO、不选数据库、不实现历史分析或新增持久账号。
- 更新导出、容器、CI 与启动文档，独立运行 Go 与 Godot，客户端依旧只需一个公开服务器根地址。

## Capabilities

### New Capabilities

- `authoritative-game-server`：服务端权威移动、校区隔离、输入协议、预测纠正及独立部署。
- `game-service-integration`：游客入场票据、Go 网关、在线状态上报与查询，以及未来认证和数据服务边界。

### Modified Capabilities

暂无已归档主规范。现有 `guest-player-session` 变更中的游客身份和交互保持；其客户端位置上报决策在本变更实现时明确被取代，需同步旧设计与现行文档，避免保留相互矛盾的运行约定。

## Impact

- Godot：`apps/client/scripts/` 的玩家、网络、校区生命周期，共享运动/碰撞生成工具、无头入口与服务端导出预设；不手工复制校园模型。
- Go：`apps/server/` 的路由、游客票据、在线快照接口、网关、测试及部署配置。
- 构建：Godot 服务端独立镜像与现有 Web/桌面导出及 Go 镜像；部署配置只引用环境变量，不提交真实凭据。
- 文档：`AGENTS.md`、README、服务启动说明及相关 OpenSpec 约定。运行迁移验收必须覆盖真实碰撞、50 人、故障恢复及 Web 实际渲染。
