# 地理网格与瓦片生成

地图通过“来源几何 → 材质网格 → 连接变体 → 物件层 → 渲染”生成。不得先画完整场景，再把整图切成小图片充当瓦片流水线。

## 坐标与网格

固定北朝上，X 向东、Y 向南；一个地面格子为 1×1 米，对应原生 16×16 像素。开发区校区 WGS84 原点为经度 121.811878、纬度 39.085291。沿用同一局部投影，不能为画面构图旋转地图、平移单项要素或重排步道。

材质取格子中心采样。湖泊采用登记水面多边形；步道采用 OSM 中心线及记录的宽度。没有实测宽度时保留估计标记，不把格子精度当作来源精度。格子的材质、来源类别与连接掩码分别保存；替换贴图不改变地理数据和碰撞依据。

## 材质与连接

涌泉湖样板使用草地、水面、红步道三种材质。草地是依据湖岸照片确定的基础地表，尚未配准的种植床不当作已定位要素。样板配置、裁切范围和依据位于 [yongquan-grid.json](../references/eda/yongquan-grid.json)。

连接选择保留 N、E、S、W、NE、SE、SW、NW 八邻域，以及中心格的材质占用位。以格子中心占用值做双线性插值，再以二分之一阈值直接生成硬像素轮廓，使阶梯边缘通过斜向瓦片衔接。这里插值的是占用数据，不是图片或颜色；不做抗锯齿、模糊或高清缩图。不再丢弃对角信息或固定为 47 种形状，只生成选定区域实际使用的连接变体。

边缘可延伸到相邻格内的局部区域，因此视觉层按“草地底层 → 水面连接层 → 步道连接层 → 岸坡层”拼装，分别保存贴图编号。材质格依旧按地理采样记录，不用经过修饰的视觉轮廓反写来源几何或通行范围。边缘轮廓与路缘颜色读取瓦片外侧两像素的相同占用场，避免斜线穿过接缝时中断。每种连接形状提供四个细节变体；变体依据世界格坐标确定，重新生成和不同裁切不会改变同一格子的样式。

地面和植被模块严格为原生 16×16 PNG。透明边界瓦片覆盖独立地表底层，不修改材质格或来源轮廓。保留的二维建筑生成图独立使用整张透明 PNG，画布为 16 的整数倍、像素密度与地面一致；这些 PNG 不参与 HD-2D 建筑渲染。不使用高清图缩小或插值滤镜伪装像素画。新增材质对时明确相应过渡，不能沿用错误底色。

统一显示像素之外，还需控制材质笔触尺度。跑道、红步道、普通步道、沥青和球场的表面颗粒使用 2×2 原生像素色块，零号变体留白，避免每格重复一像素高碎线造成细密噪点。这些材质中中心格被占用的连接瓦片也按世界坐标选择变体，避免窄路只使用零号变体而完全失去纹理。草叶、水纹、砖缝和连接边界保留各自有意义的轮廓，不通过额外缩放某一种材质改变像素密度。

湖岸表现另有独立的透明岸坡层。参考星露谷森林池塘的方向关系，朝南的岸面露出草边、土色坡面与水线阴影，朝北的岸面受前景地面遮挡；两侧转角连接这些层次，不能将同一条描边旋转用于四向。当前用 8 个显示像素表达低草岸，属于视觉估计，不是实测高程，也不把缓坡改成高崖。岸坡从相邻格的水面掩码选择并去重成原生 16×16 模块，跨格边缘连续，独立记录于 `shoreFaceCells`，不改 `materialCells`。

生成选取的区域时同时计算外侧两圈材质格和一圈像素连接格，避免裁切边缘产生假岸线或截断岸面。预览只允许最近邻整数放大，不将完整预览图作为游戏贴图。

## 独立物件

树木、灯杆、长椅、景石和建筑分别记录落地点、地面占地、显示偏移与遮挡顺序。画面高度不改变落地点；北朝上的地表保持不变，通过立起的物件和遮挡形成俯视斜视感。建筑整体绘制屋顶、可见墙面及简化窗格，按来源中的高度和层数估计外观，不能把同一立面细节复制到未经确认的朝向。

涌泉湖地面样板的物件层为空。全校地图另使用已按 OSM 区域配准的植被估计点，原始种类、区域和估计性质记入 `references/eda/planting.json`。不使用已暂缓的旧坐标区域；落在水面、道路等非绿地格上的估计点不摆放。此前景石环岛绘图不是定位依据，不能从该图反推景石、灯杆或长椅坐标。

七舍分别使用已登记塔楼和裙房轮廓，不能将整个院落拉升为塔楼。北朝上只展示从南侧可见的墙面；DUT 标识面隐藏。七舍南立面只绘制来源中已定位的局部窗格，其余未证部位保留简化体量。原 OSM 中覆盖已核对楼栋的“融苑”大范围边界未当作单体建筑，保持待核对状态。

## 生成与检查

安装 `tools/requirements.txt` 后运行 `python tools/generate_lakeside_grid.py`。默认输出到忽略目录 `.local/yongquan-grid/`；可用 `--output` 指定输出目录。生成工具从自身位置解析来源，不依赖调用目录。

局部工具输出 `grid.json`（材质、贴图、来源类别与连接信息）、原生 16×16 `tiles/`、北朝上拼装预览、材质格预览和连接变体预览。原始 OSM 数据及许可见 [来源记录](../references/eda/osm-source.json)和 [CREDITS](../CREDITS.md)。

`flat-grid-native.png` 保留仅有材质的底图；`north-up-native.png` 叠加方向性岸坡；`north-bank-detail.png` 是登记坐标范围内的整数放大细节。星露谷图像只用于离线风格分析，未进入贴图或地图输出，来源记录在湖区配置中。

## 全校生成与发布

三个校区共用本节的地面和 HD-2D 流水线。开发区使用下述原入口；凌水与盘锦运行 `python tools/prepare_campus_maps.py`，随后用 `python tools/prepare_world_map.py --campus <lingshui|panjin> --native --output apps/web/public/campuses/<campus>/world-map.png` 生成地理配准的地图窗口原片，每像素对应 10 米。

凌水原点为 WGS84 `(121.520186, 38.881499)`，裁切 2176×1920 米，接入 176 个建筑体块及两处照片配准体育设施；盘锦原点为 `(122.11917, 40.686319)`，裁切 1024×1216 米，接入 47 个建筑体块。裁切覆盖登记楼栋与 OSM 校界，不代表矩形校园红线。道路、水体、运动区和已登记铺装沿用各校区来源，不复用开发区地理数据。

来源为本地旧 3D 提交 `1e4466e78e009d1e9fed12882551a5990059f626`。`references/<campus>/campus.json`、`osm_roads.json`、`vegetation.json` 保留归档运行记录，`mapping/`、`buildings/` 与共享来源保留地面身份及照片配准；`archive.json` 记录原提交、场景路径和摘要。建筑保留有效凹轮廓、分区高度与已有立面，未知立面不补通用窗格；两处凌水内孔同时保留在模型、地图和前后端碰撞中。凌水体育场与西校区体育场迁入登记的场内结构及划线；看台地面碰撞来自旧场景实体三角形的投影，写入 `sports-models.json`，不阻挡整个运动场。

两校区沿用平面地面，不应用旧 DSM 高程。旧档案已撤下的斜视轮廓和未配准植被继续暂缓，室外设施层为空；不补缺乏依据的室内、B12/B20、完整喷泉、架空长廊或灯位。`pixel-layout.json` 将游戏出生点设在已登记主楼南侧，属于游戏站位，不是实测入口。`geometry.json` 和 `planting.json` 为生成适配数据；完整地面重生成仅需仓库记录及 Pillow，不依赖归档场景或外部目录。

仅重建两校区模型时需要 Godot、Blender 和原提交的本地缓存：先运行 `python tools/import_campus_references.py <commit>`，导入器会在 `.local/campus-models/` 建立最小 `project.godot`。用 Godot headless 执行 `tools/export_campus_buildings.gd -- <绝对临时校区目录> <绝对 campus.json 路径>`，再运行 `python tools/build_campus_buildings.py <campus>`。导出删除旧照片、程序噪声与 PBR 纹理引用，将登记结构与颜色交给共享原生像素烘焙器，生成单材质 GLB、外置最多 48 色 PNG 及逐栋清单。工具仅读取本地 Git 对象及校验后的已有对象缓存，不调用 LFS 或网络。正式资源使用普通 Git 文件；地面重生成不覆盖模型。

运行 `python tools/generate_eda_map.py`，从仓库已保存的几何、照片记录、植被点与 OSM 档案生成 `apps/web/public/campuses/eda/`。常规生成不需要外部项目目录或在线服务。只有更新已授权档案时才使用 `tools/import_eda_references.py <archive>`，导入已登记几何和照片元数据，不复制照片进客户端。

地图包含地面多层 RLE 数据、64 米分块、4 米总览数据、独立建筑 PNG 和植被原型及落地点。不生成全校大贴图；浏览器只创建视野内的精细格子与物件。地面支持水面、林地、道路、红步道、普通步道、铺装、桥面、田径场、球场和草坪，路线宽度中的估计标记保留在来源字段中。

地图覆盖开发区校区资料范围，主要建筑、两湖与体育区依资料表达。建筑仍是外观简化图，不包含室内；三轴实验室缺少立面资料，保留地面轮廓投影。运动场以来源多边形表达材质范围，未擅自补充缺少依据的内部设施或细部。没有完整测绘的绿地与高度不声称真实复刻。

## 场景材质细节

草地四种变体与屋面、墙面、玻璃各四种材质存于 apps/web/public/campuses/eda/materials，均为 16×16、每片最多 8 色的 imagegen 派生 PNG。草地直接作为四种地面原片；建筑保留原生像素密度、轮廓和颜色族，将生成材质的明暗细节映射到原屋面、墙面和玻璃遮罩，保留已有窗框、楼层线和檐边。来源与提示词见 references/eda/materials.json。

tools/terrain_tiles.py 和 tools/campus_objects.py 读取这些已提交原片，完整重生成无需再次调用 imagegen。仅刷新本批草地与建筑时运行 python tools/campus_materials.py --refresh；该操作不修改 map.json，不改变占地、建筑尺寸、原透明轮廓、道路与碰撞。其他地表和建筑结构仍沿用既有绘制方式，尚未完成逐栋造型重绘。

## 植被美术

阔叶树、柳树、针叶树和低灌木采用 imagegen 生成的独立透明素材，每类两种变体。正式原片位于 apps/web/public/campuses/eda/vegetation：阔叶树与柳树 96×144，针叶树 48×112，灌木 32×32；最多 16 种可见颜色，透明度仅 0 或 255。原片按底部接地区域登记锚点，以最近邻缩到原生画布，清理离散边缘，再拆成严格 16×16 模块。tools/campus_objects.py 直接读取已提交原片，不再程序化堆叠圆团绘制植被。

python tools/prepare_vegetation.py --refresh 重建植被模块和 plantPrototypes，清理废弃模块，保持原始植物实例位置、原型画布尺寸和地理要素不变；地面纹理名称映射保持一致。完整校园生成同样读取这些原片，无需再次 imagegen。来源与提示词见 references/eda/vegetation-art.json。沿用已实现的树冠整数像素风摆，树根固定。地图生成和材质、植被刷新会自动重新运行 `tools/build_tile_atlas.py`，将地图清单中的瓦片按顺序无缩放拼入运行时图集。

## HD-2D 建筑模型

运行时使用 `apps/web/public/campuses/eda/models/` 的 15 栋简化底模和 `models/textures/` 的逐栋像素 UV 贴图。每栋为一个材质、一张最多 48 色的 PNG；GLB 只保存几何体和 UV，通过相对 URI 加载配套 PNG。原二维建筑图保留为生成资源，不再参与校园渲染。三轴实验室无立面资料，仍只展示原占地轮廓，不补绘建筑。

`tools/build_pixel_buildings.py` 读取本地归档 3D 分支、现有地理轮廓和已登记建筑资料，调用 `tools/bake_hd2d_buildings.py` 重建。普通楼栋从有明确名称的主体体块提取底模，合并顶点和共面结构；窗框、栏杆、砖缝等细网格只作为颜色烘焙来源。图书馆和教学楼 C 区依据登记的椭圆、翼楼与高度分区重新生成连续外壳，避免旧曲面细碎网格和远景凸包造成凹口、屋顶或连接翼变形。不采用整栋凸包替代真实凹形轮廓。

贴图直接按原生像素预算烘焙：以约 8 像素/米的表面积预算选择 256–2048 的图集边长，不先生成高清图再缩小。只烘焙来源模型的材质基础色与已建窗格，不烘焙灯光、阴影或照片；表面复用已登记墙面原片的轻微颗粒，量化为最多 48 色、无抖动 PNG。实时日照、阴影和景深仍由场景处理。原始照片、旧 PBR 贴图和细节高模不进入运行资源。

来源提交、原始 GLB 路径与 SHA-256、主体对象名、建筑原点、三角形数量及贴图尺寸记录在 `models/manifest.json`。图书馆与 C 区的椭圆、外扩及高低连接翼均沿用旧版登记估计，不声称新增测绘或完整立面复刻。

重建命令为 `python tools/build_pixel_buildings.py <归档提交>`，需要 Pillow 和 Blender；用 `--blender` 指定 Blender 路径。仅从本地 Git 对象和已有模型缓存读取源文件，不调用 LFS 或网络。正式 GLB、PNG 为普通文件，不建立 LFS 跟踪或客户端下载步骤。常规前端构建直接使用这些资源；地面重生成不需要归档或 Blender，也不覆盖模型目录。

场景以米为单位，X 向东、Y 向上、Z 向南。模型 origin 的 X/Z 减去 map.json.offset 后放入校园；当前平面地面不应用旧地形 Y。建筑 footprint 和地面通行保持现有地理网格。建筑遮挡使用三维深度和前方楼体淡出，规则见前端规范。

## 开发区路灯与公告栏

`references/eda/site-fixtures.json` 保存旧版登记的室外设施、来源提交、源文件、照片引用、路段锚点及估计边界。14 盏弯臂灯来自 `exterior-details.json` 的道路顶点、沿段比例及侧向偏移；庭院 1 盏、学苑桥西侧 2 盏圆环灯和 2 组公告栏沿用 `site_fixtures.json` 的独立锚点。道路对应当前 `geometry.json` 的同版本 OSM 记录，桥头使用旧版登记的桥西端及相对站位，不将端点当作测得的台阶落点。

运行 `python tools/build_site_fixtures.py` 发布 `apps/web/public/campuses/eda/site-fixtures.json`；全校地面生成也调用此步骤。运行数据仍以共享 WGS84 原点下的 X 向东、Z 向南米制坐标记录，渲染时减去地图 offset，落在当前平面地面。生成不移动道路、湖岸、绿地或建筑，也不推断其余灯位、长椅位置及现状设施总数。

## 区域像素地图集

全屏大地图使用 `apps/web/public/world/atlas/`。浏览器只加载本地静态区域原片、校园图层、图标与配准清单，MapLibre GL JS 负责平移、缩放、地理投影及命中选择；不是游戏地面或碰撞来源。

区域覆盖 WGS84 东经 120.7–124.2、北纬 38.4–41.15，包括大连全域概览及盘锦校区。`references/city/geography.json` 保存裁切后的 Natural Earth 1:10m 海陆、城镇、道路、河流及地名；Mapzen Terrarium 高程原片和来源在同目录。工具按 Web Mercator z9 的原生像素格着色，生成 1275×1304、最多 48 色原片，北纬 40 度处约 234 米/像素，不通过高清缩图伪装像素地图。海岸与道路取来源几何，高程色带是视觉表达，不能推断林地类别。粗岸线上的校园陆地以已有 OSM 边界为准；这不是新增海岸测绘。

校园图层现使用三张完整 imagegen 插画，位于 `apps/web/public/world/atlas/illustrations/`。主要位置对照为学校地图的 lm30 二维图，last 斜视图补充建筑造型，《大连理工大学手绘四季》只作离线风格参考。完整提示词、来源与原片摘要见 `references/city/campus-art.json`。三校区按主楼广场像素样片重绘。Retro Diffusion Pixel Art Fixer Standard 以 1×1 原片像素格保留重绘分辨率，每校区量化到最多 48 色。依插画校园轮廓保留校内区域，校外背景与路网设为透明；运行时最近邻采样，建筑、道路和植被作为同一图层一起缩放，不再叠加逐栋图标或应用最小屏幕尺寸。此前逐栋素材与模型参考仍保留在来源档案中。本文游戏地面瓦片规则不约束这个独立的全屏地图插画层。

`references/city/campus-registration.json` 记录 11 个人工选择的插画地标中心，与现有 WGS84 地标占地包围盒中心配对。在 Web Mercator 平面拟合单一缩放、旋转和平移，将图像四角写入 MapLibre 图层；不局部拉伸图片，不修改校园地理数据、标签坐标、传送坐标或碰撞。当前为本地近似配准预览，控制点最大拟合残差分别约 37、12、11 米，不代表测绘精度；主校区局部道路和建筑仍有偏移。地图四角按透明裁切后的图像范围重新计算，保持原配准比例和位置。官网斜视点击框不作为建筑基底，图中额外片区不自动成为可行走区域。

更新插画或配准选点后运行 `python tools/register_campus_atlas.py`，它读取来源档案中的本地原片，调用登记版本的 Retro Diffusion Standard Python API，发布三张透明插画并更新配准记录。常规地图重建直接读取已发布图片和配准记录，不依赖原片缓存。地图点选仍使用 242 个已有地标的 WGS84 几何，像素标签独立叠加；局部美术偏移可能使图片中的建筑与命中范围不完全重合。

首次更新区域来源运行 `python tools/import_city_references.py`；常规生成运行 `python tools/build_city_atlas.py`，只读取仓库资料与已安装 MapLibre 许可。重新生成模型参考时加 `--render-landmarks`，输出仅到 `.local/city-map/model-sprites/`，需要 Blender，可用 `--blender` 指定路径；相机通过 `view_frame(scene)` 计算纵横画幅，保留完整模型边界，不会覆盖正式 imagegen 美术。生成原片和逐栋提示词缓存到 `.local/city-map/imagegen/`，运行 `python tools/prepare_atlas_art.py` 标准化全部原片，或加 `--asset <id>` 处理单栋；可用 `--source-dir` 指定原片目录。原始全球下载仅保存在忽略的 `.local/city-map/downloads/`，仓库只保留区域提取数据、所需高程与来源。正式静态构建不依赖 Blender 或在线地图服务。旧单校区 `world-map.png` 保留为生成资源，不再作为全屏大地图入口。
