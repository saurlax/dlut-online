## Purpose

定义 DLUT Online 客户端、权威游戏服务器和 Go 数据服务之间的信任及通信边界，使游客入场、在线人数和玩家查询具备明确的验证及时效语义，并为后续真实 SSO 和持久化保留一致的身份接入路径。

## ADDED Requirements

### Requirement: 同源站点与游戏入口

Go SHALL 提供简洁站点入口、现有 `/web/` 资源、版本化 HTTP API 和 `/ws` 游戏代理，保持 Web 同源与桌面根地址约定，不再承担玩家模拟或状态广播。

#### Scenario: 浏览器及桌面访问
- **WHEN** 浏览器访问首页并进入游戏，或桌面客户端使用 DO_API_SERVER_URL
- **THEN** 使用同一公开 HTTP(S) 根地址完成资源、票据和 WebSocket 请求，HTTPS 页面使用 WSS，跨源浏览器握手被拒绝

### Requirement: 一次性入场票据

Go SHALL 签发绑定协议版本及游客身份的短期一次性票据，票据 SHALL 不绑定目标校区或地图权限，游戏服须使用 API Key Bearer Auth 兑换后才允许玩家进入；游客标识 SHALL 不被作为持久账号鉴权凭据。

#### Scenario: 有效和无效兑换
- **WHEN** 游戏服兑换有效票据，或请求使用过期、已消费、伪造票据及无效 API Key
- **THEN** 有效兑换返回服务端派生身份；其余请求拒绝且不创建玩家，兑换具备原子单次语义

#### Scenario: 地图选择独立于票据
- **WHEN** 玩家取得未消费的有效票据后，选择任一现有校区建立连接
- **THEN** 三个校区均开放，签发与兑换不要求目标校区，游戏服独立验证地图 ID 存在，不执行校区权限判断

#### Scenario: 同实例切图不重新认证
- **WHEN** 已验证连接的玩家切换地图且 Go 票据接口暂时不可用
- **THEN** 切图由游戏服处理，不请求签发或兑换票据，既有代理通道正常时仍可完成切图

#### Scenario: 签发滥用和敏感信息
- **WHEN** 大量请求签发或观察客户端资源、URL 与服务日志
- **THEN** 待兑换票据与请求受到容量限制，票据仅经消息正文传递，服务端密钥不泄露到客户端或日志

### Requirement: 服务 API 鉴权

受保护服务接口 SHALL 位于 `/api/v1/`，并使用 `Authorization: Bearer <DO_API_KEY>`；Go、Godot 游戏服及其他可信平台 SHALL 通过部署环境取得 API Key，桌面客户端不得包含该 Key。

#### Scenario: 可信平台调用
- **WHEN** 调用方使用有效或缺失、无效的 API Key 请求受保护服务接口
- **THEN** 有效 Key 使用统一 API 流程完成调用，其余请求返回 401

### Requirement: 在线完整快照

游戏服 SHALL 每 5 秒向 Go 上报已入场玩家完整快照，包含实例、当前注册启动代次和单调序号；Go SHALL 仅接受受认证的当前代次新快照，并以自身接收时间确定时效。

#### Scenario: 切图统计连续
- **WHEN** 玩家在保持连接的情况下切图
- **THEN** 全程计作一个在线玩家且入场时间不变，准备阶段归原校区，提交时原子更新校区，不产生退出和重新登录事件

#### Scenario: 延迟、重复与重启
- **WHEN** 收到重复或乱序快照、上一启动代次快照，或 Go 重启
- **THEN** 旧数据不能覆盖新数据，游戏服在 Go 重启后重新注册并提交完整快照，恢复前状态不显示为正常在线

### Requirement: 公开人数的时效语义

Go SHALL 提供总人数及分校区人数查询，使用 live、stale、unavailable 区分状态；超过 15 秒无有效快照时当前人数 SHALL 为 null，不得把未知或失联当作零人。

#### Scenario: 零人和游戏服失联
- **WHEN** 正常收到空快照，或最后有效快照已超过 15 秒
- **THEN** 前者返回 live 和零人，后者返回 stale 及当前人数 null，可明确标注最后观测值与接收时间

### Requirement: 在线玩家查询权限

Go SHALL 仅向具备有效 API Key 的调用者提供当前在线玩家标识、昵称、校区与入场时间，并附时效信息；公开人数接口不得暴露明细，查询不得宣称提供持久玩家资料或历史分析。

#### Scenario: 未授权明细查询
- **WHEN** 调用者不提供有效 API Key 访问受保护接口
- **THEN** 请求被拒绝；公开人数查询仍只返回聚合数据

### Requirement: 外部数据故障隔离

游戏服 SHALL 异步调用 Go 并设置有界超时、重试和缓存，数据接口故障不能阻塞物理模拟；未成功兑换的入场不得绕过验证。

#### Scenario: 服务接口不可用
- **WHEN** Go 服务接口超时但现有游戏连接仍连通
- **THEN** 已入场玩家继续游戏，新入场明确失败，上报仅保留有限最新状态；接口恢复后在线状态重新同步

### Requirement: 后续集成边界如实记录

交付文档 SHALL 明确真实 SSO、数据库和历史分析尚未实现，说明未来身份映射、版本化保存、幂等业务操作及外部查询均由受认证的 Go 数据接口承接，不生成可被误认为真实集成的假成功接口。

#### Scenario: 检查未接入能力
- **WHEN** 检查本次路由和文档
- **THEN** 无虚构 SSO 登录、历史 DAU、留存或持久化成功响应，未来数据流程和当前仅内存能力可区分

### Requirement: 按应用范围构建
CI SHALL 使用独立 Web 与 Game 工作流按路径触发，网站变更不得触发游戏导出；API 变更 SHALL 触发两者以验证联调兼容性。版本发布 SHALL 等待两者成功。

#### Scenario: 网站改动
- **WHEN** 仅修改 apps/web 下运行文件
- **THEN** 只运行 Web 构建与镜像检查，不安装 Godot 或导出客户端

#### Scenario: 导出包校验失败
- **WHEN** 检查已导出的 PCK 或 Godot 报告脚本错误
- **THEN** 包校验在独立临时目录执行，脚本错误使 CI 命令立即非零退出，每条直接 Godot 命令最多运行十分钟
