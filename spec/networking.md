# 多人通信

## 当前实时连接

游戏启动后以已登录账号或游客身份建立同源 WebSocket，首条消息携带凭据供服务器验证，服务器读取账号角色名并广播连接、断开和聊天消息。角色、移动、聊天、指令及天气时间更新共用该连接；聊天按账号限制每秒一条，最长 200 字符。Enter 打开输入框并发送，Escape 关闭。消息平时显示约 10 秒，打开输入框时显示本次连接缓存的历史。聊天事件为在线临时消息，不持久保存。

游客使用服务端内存中的临时身份加入实时连接，和账号共用消息速率限制；游客凭据不能访问角色、背包修改或管理员指令接口。

聊天输入 `/help` 查询有权使用的指令；`/time set day|night|noon|HH:MM` 和 `/weather set clear|rain|snow|fog` 由服务端校验参数及对应权限并广播临时世界设置。账号通过 user_roles 关联 roles，roles 通过 role_permissions 关联 permissions；集合仅供管理员管理。初始化 admin 角色拥有时间与天气指令权限，并在目标邮箱已存在时绑定该账号。同步实际时间与天气每 15 分钟执行一次。

服务端每 10 秒发送 WebSocket Ping，客户端断线后按指数退避重连；失效凭据停止重连。未确认的消息不自动重发。原聊天和天气 HTTP 接口暂时保留兼容。

客户端连接就绪后立即发送应用层 `ping`，随后每 2 秒发送一次，服务端以 `pong` 回传相同 `id`。客户端使用本地单调时钟测量往返延迟，供右下角 HUD 显示；断开连接时清空读数。

## 当前玩家同步

Go 从静态发行包的 `map.json` 和 `site-fixtures.json` 加载通行格、建筑轮廓、路灯及公告栏碰撞。角色以独立的随机公开连接 ID 加入同一开发区世界，出生时优先避开其他角色；公开快照不包含账号 ID、游客凭据或背包记录。账号外观与已穿装备从数据库读取，游客使用预设装束；更换装备后重新读取外观，不接受客户端自报装备或身份。

客户端逐帧预测移动，每约 50 毫秒批量发送方向、跑步状态、步长及递增序号，单批最多 12 步。服务端拒绝非法数值和超长步长，按自身经过时间限制累计模拟预算（最多 200 毫秒余量），统一计算速度、斜向归一化与碰撞，不接受客户端提交坐标。步行 3 米/秒，Shift 跑步 6 米/秒；摇杆采用相同规则。服务端每 100 毫秒发送自身及 160 米内玩家的完整状态、外观和已确认输入序号。客户端重放未确认输入校正自身位置，以约 100 毫秒插值渲染其他玩家、朝向及走路动画。

停止输入后不继续模拟移动；超过 250 毫秒未收到输入的远端角色显示站立。客户端断线时停止预测并清空远端角色，重连后使用新连接快照。连接关闭时服务端移除角色。当前位置只在单进程内存维护，刷新或重连返回出生点，尚未持久化位置。

地图跳转只发送登记地标 ID，落点由服务端按同一碰撞规则选择。跳转增加位置代次，旧代次输入不再执行，客户端清空跳转前的预测队列。位置和输入不通过 PocketBase 数据库订阅同步。后续 Pion 方案仍是设计目标，不是当前传输方式。

## 游戏数据通道设计目标，尚未实现

每位玩家与 Go 权威服务器建立一个 WebRTC PeerConnection，由 Pion 作为服务端协议实现。玩家之间不建立全连接网状网络，服务器统一校验输入、模拟移动和筛选附近相关状态。

首页负责登录、账号续期与角色初始化，并在进入校园前申请短期游戏票据。campus 只使用该票据进行 WebRTC 准入，不承载密码、OIDC 或账号续期流程；票据无效或游戏会话失效时回到首页重新准备。信令服务必须验证票据并将连接绑定到账号，不能信任客户端启动快照。游戏票据及 WebRTC 接口目前尚未实现。

HTTPS 负责账号，当前角色、移动、聊天、指令和天气使用 WebSocket。WebRTC 游戏数据通道和信令尚未实现。

## 数据通道

| 通道 | 可靠性 | 消息 |
| --- | --- | --- |
| control | 可靠有序 | 进入地图、角色加入退出、交互请求与结果 |
| state | 无序，最大重传次数 0 | 高频输入、权威快照 |

通道之间没有统一到达顺序。消息携带协议版本、连接代次、地图代次、输入序号或服务端时间步，拒绝旧连接、旧地图和迟到状态。丢失输入不能造成永久移动：传输需携带可替代的当前输入状态，并设置服务端超时停止；具体频率、超时和容量在原型测量后确定。

可靠交互仍需操作 ID、业务结果和幂等处理；可靠传输不等于断线后业务必定提交。状态快照必须允许丢包恢复，增量编码须有已确认基线或完整快照恢复策略。

## 模拟与缓冲

Go 以固定时间步推进世界；网络回调只解码、校验并投递有界输入队列。身份取自连接绑定，不能相信消息自报账号。检查消息长度、数值范围、频率和序号，移动结果由服务器根据自身时间与碰撞数据计算。

客户端进行本地预测、权威修正和远端插值。传输队列有界，拥塞时合并或跳过过时快照，不能无限排队。素材与大地图文件走 HTTPS，不占用游戏数据通道；多个 DataChannel 共享拥塞控制，不能认为通道完全隔离。

## 部署

优先采用 Pion UDP 端口复用。公开 ICE 地址必须与实际入口匹配，不因 HTTPS 域名代理而假设 UDP 也走代理。EdgeOne 普通七层接入承载网页、API 与信令；WebRTC 数据代理需要企业版四层 UDP 服务，并验证 ICE、DTLS、会话保持和真实 IP 头部兼容性。

受限网络需评估 TURN。客户端与服务端均实现有界协商、心跳、断开、清理和重连生命周期；账号服务可用不代表游戏连接可用。初始化阶段不开放信令接口，不声明已经实现 Pion、TURN 或 WebRTC 回退。
